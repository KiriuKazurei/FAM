# 一次复制有了中间状态：传输是任务，不是调用（增量 21）

## 1. 描述问题

14 号账里被称做"最实际的坑"的那个"中"：

> 没有进度。跨卷复制一个大文件时界面不会显示任何东西——调用是同步的，发生在 GUI 线程上，
> 所以**大文件会把窗口冻住**直到核心返回。归属：把 `pathOp` 推到工作线程，或者在核心侧
> 提供进度；两者都要求先有"一次写可以取消"的语义。

上一增量把传输变成了可撤销，撤销的逆操作走的还是同一条同步调用——撤销一个大文件的
跨卷移回，一样冻。

## 2. 分析问题

### `fs::copy` 是一次调用，一次调用没有中间

进度与取消的共同前提是把"复制"从单次 `fs::copy` 拆成块：1 MiB 一块，每块之后报一次
进度、问一次要不要继续。这个粒度就是取消的粒度——一个人说停之后，传输最多再走一块。
设计上的三个决定：

- **取消前的第一问在第一个字节之前**。回调在循环外先调一次（`bytes=0`），所以"刚点完
  取消"不是"又拷了一整块"的同义词。测试钉住这个：回调答一次 false，目标上什么都没有。
- **"被取消"要自己打扫**：部分副本被移除，"cancelled"意味着"什么都没到达"。源永远
  不动——取消动的是目的地，不是来源。
- **同一卷的移动没有中间**：`rename` 是原子的，进度回调零次调用。测试钉住"移动的进度
  回调零次"——把"移动也走了分块"这类想象当场拦下。

### 异步放在哪一层：任务住核心，不在壳里开线程

把 `pathOp` 推到壳的 QThread 里能治冻结，但治不了进度与取消——同步 ABI 的回答里没有
中间。所以任务住在核心：`fam_transfer_begin`（回答 `{"job":N}`，字节未动）→
`fam_transfer_poll`（状态 + 字节，**终态只答一次**，答完即退役）→ `fam_transfer_cancel`
（请求下一块后停）。三个入口，导出 30→33。

三个随之而来的决定：

- **验证跟着任务走**。同步调用在入口做的检查（永不覆盖、父目录在）触的是文件系统，进了
  任务就在任务里做——拖放时的拒绝（同名就拒）从"当场一句"变成"下一拍一句
  `failed` + 原句"。壳的入队行因此说"queued"而不是"moved"，完成的话由拍子说。
- **审计两行**：`path.transfer.begin` 在开始（谁、去哪、动作），`path.transfer.end` 在
  **第一次观测到终态的那一拍**（结果 + 字节数）。结束线由观测者写而非线程写，因为审计
  的 `&mut` 借用住在核心——代价是"核心返回后壳从未 poll"的任务没有结束线，记为残留。
- **终态只答一次**：观测到终态的 poll 把任务从注册表退役，第二次 poll 回答
  `unknown transfer job N`。注册表里只有运行中的工作，"谁清理"就不成其为问题。

### 撤销的入栈时机跟着改

撤销条目原来在 drop 时入栈——异步之后那是"还没发生的传输"。改为**任务 done 的那一拍
入栈**：撤销一个运行中的东西，撤的是一个半成品。

## 3. 解决方式

- `crates/fam-svc-fs`：`transfer_with(from, to, action, progress)`——`transfer` 成为
  `&mut |_| true` 的特例；`copy_chunked` 1 MiB 一块，回调前三问 + 每块后一问，取消清扫
  部分副本，权限随 `fs::copy` 照搬；`Error::Cancelled` 变体。四条测试：进度单调且总和
  等于文件、首块前取消零残留、中途取消清扫且源不动、同卷移动零回调。
- `crates/fam-ffi`：`TransferJob{cancel, state, from, to, copy}` 注册表（`Mutex<(u64,
  HashMap<u64, _>)>`），复制线程持 Arc 更新字节；`fam_transfer_begin`/`poll`/`cancel`
  （导出 30→33）；终态首次观测写 `path.transfer.end`。过线测试：copy 到 done（字节相等、
  源在）、move 到 renamed（源走）、大文件取消（两个终态都诚实——cancelled 则无残留）、
  终态退役后 poll 被拒。
- `apps/fam-shell`：`handleDrop` 改为 `transferBegin` 入队（队列行说 queued）；
  `pollTransfers()` 在 250ms 的拍子上轮询——运行中聚合字节进状态行，done 入撤销栈、
  cancelled/failed 成为句子（保住拖的形状：哪个文件夹、哪个动词）；Esc 向所有排队任务
  发取消。self-check 的两个传输步骤各加 `waitForTransfersForSelfCheck()`——盘上断言
  说的是已完成传输，队列先清空。
- `abi-smoke`：`job=1` 进导出闸门行——begin → poll 到 done（字节数 = 源大小）→ 终态退役
  后二次 poll 被拒。

## 4. 解决方式效果评估

### 正面证据

**无头那一步的原文**（fresh 树，light 与 dark 两遍一致）：

```
transfer move into ...\tree: done, 0 byte(s)
transfer copy into ...\tree\2024-合同: done, 4 byte(s)
self-check undo: copy-undone=1 (origin=1 copy=0) move-undone=1 (origin=0 dest=1)
```

拖放进来的两个任务在拍子上各自结算并完成，撤销照常在磁盘上过。三个 drop 步骤的盘上
断言（`exists=0/1`、`exists=1/1`、`already there`）在结算等待之后原样全绿。

**核心侧**：`cargo test --workspace` 38 个二进制全绿（fam-svc-fs 四条、ffi 一条大测试）；
clippy `-D warnings` 干净；fmt 干净。

**壳侧**：light/dark 两遍退出 0，对比度 17 对全过，17c–20 的全部断言原样绿；
`abi-smoke` 连跑两遍 `-> ok`（新 `job=1`）；`model-smoke` ok。

**冻结的消除是结构性的**：drop 的调用路径里不再有 `transfer`——`transferBegin` 只做
字符串转换、线程 spawn、一行审计，微秒级；字节的世界在另一条线上。这条没有"实测数字"，
因为它不是一个变快了的操作，是一个不再占 GUI 线程的操作——证据是路径的形状本身，
以及 self-check 里在旧实现下会冻结的那类大文件传输在结构上已无法到达 GUI 线程。

### 三处自记

1. **哨兵的两次设计**：第一版用 `const io::Error` 加指针比较当"已取消"哨兵——`io::Error`
   非 const 可构造，指针比较对不同分配也不成立，编译器当场拦下。改成 `CopyStop` 枚举
   （Cancelled / Io），读失败与说停从此在类型上可分。
2. **abi-smoke 的第二轮删除断言红过一轮**（20 号账的旧病复发）：这次不是命名反了，是
   我把"轮询到自己退出"写成了假设机器速度的固定次序。修法与别处一致——循环到终态，
   上限由 deadline 守着。
3. **`pollTransfers` 对 unknown job 按 failed 处理并让条目退役**：正常的拍子流里它不该
   发生（终态在第一次 poll 就取走），但一次额外的拍子如果来了，把条目挂着的代价是永远
   的重复报告——退役是安全的方向。

### 代价

- 每个传输一条线程（分钟级的大传输数量以一计，不为并发设计）；每块一次回调里的
  锁（`JobState` 的 Mutex，纳秒级）。
- 拒绝的时序变化是行为变化：拖放的"同名就拒"从当场一句变成下一拍一句。状态行的队列
  句相应改说 "queued"——这是语义上诚实的一步，但确实是一个人能察觉的差异。
- 一次传输两行审计（begin + end）；"begin 后从未 poll"的任务没有结束线。
- fam-svc-fs 约 90 行、ffi 约 200 行、壳约 120 行。

### 残留风险与局限

1. **进度以字节计，不按文件分**：一次 drop 的多个文件各自成为任务，状态行聚合的是
   运行中任务的字节——"第 2 个文件、共 5 个"不显示。要按文件报得把一次 drop 合成一个
   批任务，是另一层。严重度：低。
2. **大文件的撤销逆操作仍同步**（撤销跨卷移回 = 一次大复制在 GUI 线程）：undo 走
   `pathOp` 的旧路。撤销也应该走任务——但撤销的失败回栈语义与异步完成时机纠缠，
   值得独立一步。严重度：中（与 14 原账同因，范围已缩小到撤销这一条路）。
3. **`pathOp` 同步入口仍在**（撤销与 abi-smoke 在用），一条愿意冻结的合法后门；
   撤销改走任务后它可退休。严重度：低。
4. **begin 后从未 poll 的任务没有结束审计线**；任务的取消标志在核心关闭（`fam_core_free`）
   时不等待——句柄释放与运行中任务的生命周期关系未定义。严重度：低（壳的生命周期覆盖
   它，但 ABI 的其他调用者要自己知道）。
5. **14 的最后一个"中"原地未动**：拖拽悬停无高亮（主题层一条规则）。归属不变。
