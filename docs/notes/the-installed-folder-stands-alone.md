# 安装出来的文件夹自己站得住（增量 26）

## 1. 描述问题

增量 15 建立的验收方式（清空 PATH，`cmake --install` 产出的文件夹必须自己跑通全部闸门）
此后经历了 16–25 九个增量，其中新增了六张截图、一套键盘命令、异步传输与撤销——**这份
验收没有在当前构建上重跑过**。15 号账的话："装完的文件夹里只有 Windows 系统目录在
PATH 上也能起——这正是这条命令要买的东西，所以它也是这条命令的验收方式。"

## 2. 分析问题

重跑的意义不在"打包规则变了没有"（`FamDeployQt.cmake` 未动），而在**增量 16–25 的全部
新表面**（筛选栏、记号、对话框、撤销、异步传输）在部署形态下同样走闸门：windeployqt
对新增的 Qt 依赖（若有）是否部署、新对话框的主题在部署形态是否成立、self-check 的时间
线在无调试符号的真实产物上是否仍能在时限内走完。

## 3. 解决方式

`cmake --install` 两包（fam-shell / fam-design），然后按 15 的验收原文执行：配置指向
fresh 树，`set PATH=C:\Windows\system32;C:\Windows`，运行
`--self-check --self-check-mutate`。

## 4. 效果评估

**验收通过**：退出 0；断言读数全 1（含 23/24 的键盘命令、25 的撤销、22 的拖悬截图）；
对比度受门槛 18 对全过；icons 21/21/21 pending=0；ipc retries=0。英文 README 的
Installation/Instructions 两节从 "Not available yet" 补为实文（安装命令 + 五条使用说明）。

**一处自记**：对话框截图的 `listed=2`——grab 步的 processEvents 泵让 5300 的定时器在
tagsForSelfCheck（5200，dual 块进行中）的泵里提前跑，拍到了 dual 块的中间态。无断言
受害（截图步骤只断言自己种的标签），但这是时间线竞态类的又一实例：步骤间的隔离靠
间隔与泵的时机，每加一步都在重排别人的窗口。归属：如果再犯，步骤该自带"仅断言自己
种的标签"的约定（本步已是如此，受害为零）。
