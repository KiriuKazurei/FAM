## 1. 描述问题

要求是"界面风格设计为 Ant Design 5 样式，并且继续完成未完成的内容"，同时明确
**原项目界面设计保持独立**。

改之前的事实：`grep -rn "setStyleSheet|QPalette|setFont" apps/fam-shell/src/` **零命中**——
壳从来没有自己的样式，全部跑在 Windows 原生控件外观上。所以这不是"改配色"，是从零建一套
设计体系；而它又不能落到产品窗口上。

要定的不是画哪个窗口，是三件事：

1. 样式放哪，才能既看得见又不碰到产品；
2. token 从哪来，凭记忆敲还是量出来；
3. "Ant Design 5 样式"和"读得清"冲突时，谁让步。

## 2. 分析问题

### 2.1 为什么是独立程序，不是壳的一个开关

最省事的写法是给 `fam-shell` 加 `--theme` 并把样式表挂上去。这条路被"保持独立"否了：
一旦样式表进了壳，改设计就是改产品窗口，而样机的价值恰恰是**先看再说**。

所以 `apps/fam-design/` 是独立的 CMake 工程，只链 `Qt6::Widgets`：不链 `famcore`，
不依赖任何 Rust crate，读目录用 `QDir`。它和壳之间唯一的耦合是**词汇**——
`PreviewModel` 的角色名（`NameRole/KindRole/SizeRole/…`）和 `fam_core::Kind` 的九个桶
按同一个顺序对齐，因为样机说的是另一种词，就等于样机白做。

代价说清楚：样机里没有监视、分页、标签、轮询，也没有 shell 图标（那要 `shell32`）。
它是长相的样机，不是行为的样机。

### 2.2 token 不能靠记忆

上一增量刚因为凭记忆敲 SHA-256 轮常量敲错 5 个而写过一条教训，这次先去官方页把亮色 map token
抄回来（`colorPrimary #1677ff`、`colorText rgba(0,0,0,0.88)`、`colorSplit rgba(5,5,5,0.06)`、
`borderRadius 6`、`controlHeight 32`、`fontSizeSM 12` …），再动手。

暗色没给全：官方暗色页只落到一个底基 `#141414`，其余是运行时按算法算的。所以暗面**按 antd 的
算法派生**（同一套透明度阶梯，只是底从黑换成白），派生的对不对不靠我说——
`contrastReport()` 每次启动把**这个主题真正画在屏幕上的**每一对文字/背景算一遍 WCAG 比值。

这一步抓出两个真问题，都不是"值抄错了"：

1. **暗色气泡白字压在近白底上，实测 1.35:1。** 样式表里 `QToolTip { color: #ffffff }` 是我硬写的，
   而 antd 暗面的 `colorBgSpotlight` 是 `rgba(255,255,255,0.85)`——**暗面的气泡是亮的**。
   亮面看不出问题，暗面整条提示不可读。修法是加一个 `onSpotlight` token，
   亮面白、暗面 `rgba(0,0,0,0.88)`，报告里那一行也从硬写白改成取 token。
2. **实心按钮与"作为文字的蓝"过不了 4.5:1。** 白字压 `#1677ff` 实测 **4.10:1**；
   `#4096ff` 当 14px 正文压在白底上实测 **2.99:1**——而后者正是 antd 默认按钮 hover 的字色。
   这不是抄错，是 antd 默认值本身在这条线上不达标。

### 2.3 冲突怎么判：一个 token 名，两种职责

antd 的 `colorPrimary` 同时被用来"当边框/底的蓝"和"当文字的蓝"，前者不需要 4.5:1，需要。
所以这里把两者拆开：`primary`（交互色，用于边框/选中底/焦点）与 `accentText`（**文字**必须是蓝的
地方）。拆完：

| 位置 | antd 默认 | 这里 | 实测 |
| --- | --- | --- | --- |
| 亮面实心按钮底 | `#1677ff` | `#0958d9`（blue-7），hover 更深 | 白字 **6.16 / 7.08 / 8.80:1** |
| 暗面实心按钮底 | `#1677ff` | `#4096ff` + **深色字** | **6.30 / 8.15 / 4.71:1** |
| 作为文字的蓝 | `#1677ff` / `#4096ff` | 亮 `#0958d9`、暗 `#4096ff` | **6.16:1** 两边都过 |
| 滚动条滑块 | 很淡 | 提到三级文字色 | **3.35 / 3.83:1**（非文字线 3.0） |

亮面按钮 hover 走**深**不走浅，是被这条逼的：antd 的 hover 变浅只有在其白字 4.10:1 的前提下才无害。

两处**保留** antd 原值，并且让报告点名而不是装没测：输入框边框 `#d9d9d9`（**1.41:1**）与
禁用文字（**1.83:1**）。前者是"要不要让整个表单明显变重"的取舍，后者 WCAG 1.4.3 本就免除禁用件；
两者在报告里标 `免除` 并照旧打印比值。**免除不等于不测**——这是这份报告唯一的可信之处。

结果：亮暗两套各 15 对，受门槛的 13 对**全过**（正文 4.5:1，大字与非文字 3.0:1）。

### 2.4 Qt 做不到的三件事

1. **焦点环**：antd 用 2px `box-shadow`，Qt 样式表没有 box-shadow。退化成 1px 边框换色；
   把边框从 1px 撑到 2px 会让输入框里的文字横移 1px，比没有光环更糟。
2. **动画**：`motionDurationMid 0.2s` 无处可用（样式表没有 transition）。hover/press 是瞬时换色。
3. **省略号**：`QLabel` 只裁不省略。列标题按标称列宽预先 `elidedText`，
   列比标称宽时名字整段显示——**宁可少裁不可多裁**。
4. 顺带一条：样式表没有变量，所以 `buildSheet()` 用 `{{token}}` 占位一次替换；
   少一个映射项就会把 `{{xxx}}` 原样送进样式表，Qt 会**逐控件**在 stdout 报解析错。

### 2.5 为什么行必须自己画

模型给的 `DisplayRole` 是 `"名字  18.0 KB  [document]"` 一整串：一个颜色、一个字号，
而且**每个文件夹都印 `0 B`**（它的 size 字段是 0，不是"没有大小"）。
pieces 本来就在不同角色里（`NameRole/SizeRole/KindRole`），所以视图可以各给各的权重：
名字 `colorText`、数字 `colorTextTertiary`、类型画成 Tag（`colorFillSecondary` 底 +
`borderRadiusSM` + 12px），文件夹既不画 Tag 也不印 `0 B`，只拿 demi-bold。

**一旦委托自己画文字，它就必须连底一起画**——视图不再对这一行套用任何 `::item` 规则。
第一版在样式表里同时写了 `#fileList::item` 和侧栏 `::item` 两套规则，前者是死代码；
删掉，并把"委托拥有行"这件事写进注释，免得下次又有人往样式表里加一条不生效的选中色。

图标槽 16px **永远占位**，画不出图标时画一个单色线稿（文件夹/折角页）：
产品里图标是工作线程晚点给的，槽位不占就会在答案落地那一刻把整列名字横移，
而横移的文字是点不准的。

## 3. 解决方式

```
apps/fam-design/
  CMakeLists.txt        只链 Qt6::Widgets
  src/theme.{h,cpp}     Tokens（亮/暗同一算法）→ buildSheet() → contrastReport()
  src/preview.{h,cpp}   窗口：工具栏 + 驱动器栏 + 两列 Miller + 状态栏
  src/previewmodel.{h,cpp} QDir 读真目录，角色名对齐 fam_core::Kind
  src/rowdelegate.{h,cpp}   行的画法（名字 / 数字 / Tag）
```

组件形态靠 object name 选，名字一处列全（`Theme::primaryButtonName()` 等），
调用点编不出样式表里没有的名字。`Fusion` 而非原生 Windows 样式：
这套外观完全来自样式表，而原生样式会在样式表沉默处画自己的渐变与焦点辉光。

`--shot` 是截图模式（渲染 → 存图 → 退出），两种主题各跑一次，对比度表随 stdout 一起出来。

## 4. 解决方式效果评估

### 4.1 正面证据

- 构建：`cmake --build` 通过；`git status` 证明 `apps/fam-shell` 与 `crates/` 一行未改。
- 对比度：`fam-design.exe --theme light|dark` 各打印 15 对，**受门槛的 13 对 0 对不过**；
  暗面气泡那一行修前是 `1.35:1 不过`，修后 `12.79:1 过`（同一个位置，同一个函数）。
- 视觉：两张截图逐张看过。`docs/` 真内容：左列 `history`/`notes` 两个文件夹 + 三个 `.md`
  带 `document` Tag 与右对齐大小；右列 `history/` 里 `coreStruct.markdown`、`后端结构树Java`
  这类中英混排名字正常排版，没有豆腐块。驱动器栏 `D:\` 标为选中（浅蓝底 + 蓝字），
  与列里显示的 `docs` 所在卷一致。
- 交互都是真的：搜索框 `textChanged` 过滤、类型下拉过滤、"按名称/大小/时间"改排序、
  表头点击循环排序、左列点文件夹出右列、"打开文件夹…"是真对话框、右上角按钮换主题
  （换的是 token 表，样式表与委托同时跟着变，不是两张表）。
- 两处运行期缺陷是**跑出来的不是读出来的**：`--dir` 被驱动器栏的初始选中冲掉
  （选中一个行就等于"给我看这个卷"，构造末尾那次 `setCurrentRow(0)` 把调用方指定的目录丢了）；
  卷匹配拿反斜杠的输入去比正斜杠的根，永远不匹配，于是标记错卷。
  两条都在截图里看得见，修完重拍确认。

### 4.2 代价

- 多一个独立 CMake 工程、约 1,100 行 C++（其中 `theme.cpp` 一半是样式表文本）。
- `covers`/`contrastPairs()` 每次调用重算 15 对（含开方），只在启动和状态栏刷新时跑；
  **未实测**耗时，量级上远小于一次目录读取。
- 双份词汇表：`PreviewModel` 的角色与 `FamListModel` 的同名但**是两个类型**。
  对齐靠注释里那句"按 `fam_core::Kind` 的声明顺序"，没有编译期保证——
  这是"独立"的必然代价，采纳进壳的那天应当合并掉。
- 样式表是替换出来的，不是编译期检查的：新增 token 忘了进映射表，会在运行期逐控件报解析错。

### 4.3 没解决与不做

1. **产品窗口没变样**。这是样机；`apps/fam-shell` 仍是原生外观。采纳是一次单独改动，
   而且必须连着做壳自己的三件事：真图标（`IconCache` 已有）、分页/监视下行的重绘时机、
   以及壳的 `--self-check` 时间线在新样式下重跑一遍（它数的是图标提取/销毁与 IPC 次数，
   换样式不该改数，但没验证过就不算数）。严重度：这就是当前状态，不是缺陷。
2. **没有 shell 图标**：样机不链 `shell32`，画的是单色线稿。严重度：低（样机属性）。
   归属：若采纳，接 `IconCache`。
3. **焦点环与过渡动画做不到**（§2.4）。严重度：低，是 Qt 样式表能力的边界。
4. **输入框边框 1.41:1、禁用文字 1.83:1 保留 antd 原值**。要过 3:1 得把 `colorBorder` 提到
   `#949494` 一档，整个表单会明显变重——那是另一次设计决定，不该顺手做。严重度：低。
   归属：真采纳时连同 `colorLink` 一起定。
5. **列标题的省略按标称列宽**，列被拉得比标称窄时可能仍裁不准。严重度：极低。
6. **暗面不是逐组件核过 antd 的组件级 token**（Menu 的 `itemSelectedBg`、Table 的
   `headerBg` 等在 antd 里各有派生值），这里统一由 `Tokens` 的一套底派生。
   视觉上自洽，但与 antd 暗面组件默认值不会逐像素相同。严重度：低。
   归属：若要逐组件对齐，需要把 antd 的 component token 表也搬进来，那是另一个量级的活。
7. **样机没有测试**。它是给人看的东西，判据是对比度表 + 两张截图；
   没有 QtTest 用例。严重度：低。归属：采纳进壳时由壳的 `--self-check` 承担。
